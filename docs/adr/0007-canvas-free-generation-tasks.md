# 库级无画布生成任务路径

2026-11-01,69/70 号票 grilling 定案。角色库抽屉(AssetDrawer)挂在 IP 详情页、没有画布上下文,但 70 号票要在抽屉里原生发起设定图生成——第一个「生成动作的家不在画布上」的场景;canvas_tasks 至今全部语义以画布为锚,由此产生「无画布任务怎么放」的架构取舍。

## Context

canvas_tasks 的任务行、素材归属、转存键、审计标记、进度面板全以画布为锚:`POST /canvases/:id/tasks` 要求画布存在;素材行 `ip_id` 由任务 canvas_id 查画布得出;转存键 `canvases/{canvasID}/{taskID}/{kind}.{ext}`;来源标记 `canvas=<id> task=<ct> node=<id>`;生成记录面板按画布列举。要在无画布的 IP 详情页发起生成,就必须给任务找一个「家」——扩任务模型、造宿主画布、还是绕开任务模型,四条路成本与概念债差异很大。

## Decision

1. **canvas_tasks 放开无画布任务**:任务行允许 `canvas_id=0`、`node_id` 空;双方言加列 `ip_id`(0 = 画布任务,存量行不回填)。无画布任务的 IP 归属直接在任务行——worker 素材归属读任务行 `ip_id` 优先、画布任务照旧查画布(存量行为不变)。
2. **新端点族挂 canvas/server JWT 会话面**:`POST /api/ips/:id/tasks` + 列表 + 单查(轮询),kind 先收 image;端点形状不排他,场景/道具将来复用另票。
3. **产物对象键新前缀 `ips/{ipID}/{taskID}/{kind}.{ext}`**:素材三分归档(canvases 任务产物 / uploads 用户上传 / relay 直连转存)增补为**四分**,新前缀语义 = IP 级库生成产物;48 号票跨前缀复用与按 object_key 计数删除防护语义不变。
4. **来源标记** `ip=<id> task=<ct> gen=asset`;admin 用量审计 source 过滤加 `asset` 档。
5. **进度与可见性**:生成记录面板(按画布查)不见此类任务——进度由发起对话框承担,产物枚举兜底在 admin 素材页。

## Considered Options

- **隐藏系统画布**(每 IP 一张不可见宿主画布):零 worker 改动,但要引入「隐藏画布」新概念——列表过滤、IP 画布计数、删除语义一串要跟着改,且这些任务会堆进宿主画布的生成记录面板。概念债 > schema 债。放弃。
- **同步直调网关**(照 analyze/反推先例):analyze 是秒级聊天才撑得住同步 HTTP;生图分钟级,nginx `proxy_read_timeout` 缺省 60s 会掐死长请求,且丢掉 worker 的重试/重启恢复/失败退款纪律。放弃。
- **抽屉里选宿主画布**(生成前挑一张该 IP 的画布):零后端改动但 UX 拧巴,任务混进无关画布的生成记录。放弃。

## Consequences

- 「任务必有画布」的全局假设作废:凡按 canvas_id 查画布的代码都要面对 `canvas_id=0`(当前仅 worker 归属与转存键两处消费,改动面可控;后续新代码同此纪律)。
- 无画布任务照常离线续跑(worker 不依赖浏览器),但发起对话框关闭/刷新后进度不可见;前端锚定映射是内存态,刷新丢失后产物仍在库、可从抽屉手动锚。
- 库级生成从此有标准路径:场景/道具及将来一切「非画布生成」场景复用此路径与端点形状,不再逐个重新议架构。

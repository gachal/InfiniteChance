# IP 企划容器与画布类型化

产品定位自 2026-10-24 起从「通用画布创作工具」重塑为「打造 ACG IP」(50 号票):进入应用第一层是 IP 企划,下挂动画/游戏/漫画/通用四类画布,画布分通用节点与特色节点。依据业界调研——迪士尼/漫威/任天堂/宝可梦/集英社/吉卜力的共同工件集(世界观圣经、角色圣经含设定图、美术风格指南、大纲、时间线、关系图),World Anvil/Campfire/Plottr 收敛出的「容器 → 类型化实体库 + 视图 + 资产库」标准 IA,以及 AI 工具(LTX Studio/Sudowrite/Scenario 等)全部以项目为第一层、而「设定图锚」这一动画工业验证 60 年的一致性机制在 AI 工具中全部缺席的现状。完整纪要与来源见 `.scratch/infinite-chance/research/ip-methodology.md`。

定案四条:

1. **两层结构**:IP(企划/作品宇宙)→ 画布,不引入「IP → 作品 → 画布」中间层——用户心智与业界工具 IA(World Anvil 的 World → Articles、Plottr 的 Series → Books)都是两层,多一层是未来负担。画布必须归属 IP(ip_id NOT NULL),存量由启动自愈迁移建「默认 IP」收编,保证第一层永远干净、不出现第二套入口。
2. **类型注册表驱动**:canvases.type 存字符串、后端不校验枚举——与「服务端不解释图 JSON」哲学同源;前端一张类型注册表驱动名称/图标/定位描述/特色节点集/面板过滤,将来加「小说画布」= 前端加一项,后端零改动。代价:类型拼写错误服务端不拦,接受(单管理员,前端注册表是唯一写入方)。
3. **角色是 IP 级实体,不是画布节点**:one source of truth——角色设定(含三视图/表情集/色板等设定图)挂 IP,各媒介画布引用同一份(51 号票存储面、52 号票消费面:角色引用节点为通用节点)。Lucasfilm Story Group 的启示:IP 工厂的差异化能力不是某部作品,而是「正典维护系统」。
4. **素材带 IP 归属**:产物经画布传导、上传挂 IP、0 = 全局(直连/历史行自然形成,不做主动上传为全局的入口)——素材库从全局杂物间变成 IP 资产台账(DAM 语义)。

## Considered Options

- **类型后端硬枚举**:每加类型都要动后端校验与双方言 schema,与本项目「前端注册表 + 服务端不解释」方向相反,放弃。
- **IP 下再分作品层**:与用户两层心智冲突,业界工具也都是两层,放弃。
- **角色卡 = 画布特色节点**:跨画布要手动复制、无单一事实源,违背 IP 一致性的根本诉求,放弃(见定案 3);「角色库 = 一张特殊画布」同理否决——实体库需要结构化字段与类型化设定图,自由画布承载不了表单语义。
- **IP 删除级联**:画布是核心资产,级联删的破坏半径不可接受;改为有画布或有直接归属素材即拒删,级联与归档都放弃。
- **素材上传时手选归属**:多一个必答项且易错;改为画布内上传自动挂画布 IP、IP 详情页上传挂该 IP,行为可预期。

## Consequences

- 后端从此解释「画布属于哪个 IP」这一个事实(列表过滤、删除拦截),但仍不解释图内节点/边——领域边界只推进一层,画布内部自由度不变。
- 特色节点(53-55 号票)逐类型演进时,每个节点类型必须声明「适用画布类型」,通用节点全类型可见;机制随 50 号票落位(落地时全部现有节点为通用,行为暂无差异,是有意的中间态而非遗漏)。
- 存量迁移是启动自愈式(建默认 IP + 回填 ip_id/type),无独立迁移脚本;仅「存在 ip_id=0 画布行且 ips 表空」时触发,默认 IP 改名后不会重复创建。
- 画布移动不改历史素材行归属(历史行不清洗原则):旧产物留在原 IP 名下,新产物随新 IP。

# 通用画布与节点分组(画布类型退役)

2026-10-24,53-55 号票 grilling 中推翻 [ADR 0004](0004-ip-container-and-canvas-typing.md) 定案 2 的「画布类型 + 特色节点」双轨:画布回归通用,节点全画布可用,组织下沉到节点分组。

## Context

0004 定案 2 引入 `canvases.type`(animation/game/manga/general 四类)的目的只有一个:给「特色节点」提供挂靠面——特定媒介的专属工具只在对应画布出现。机制随 50 号票落位,但落位即空载:适用性注册表全部 `'all'`,类型对任何节点行为零影响。53-55 三类规划工件(絵コンテ/ネーム/关卡)切票时重新审视:它们是数据结构自身完整的工作件(整图 JSON、后端零改动),不依赖画布媒介语义——「特色节点」成了没有内容的机制。且单用户创作早期媒介混沌,一张画布混用预演台 + 分镜 + 关卡是真实工作流;方法论研究自己的落点是「画布作为自由空间承载非表单工件」,与「这张画布只许摆某类节点」互相拧巴。

## Decision

1. **画布回归通用**:节点类型不再声明「适用画布类型」,全部节点全画布可用;`NODE_TYPE_APPLICABILITY` 过滤机制删除。
2. **组织下沉到节点分组**:编辑器工具栏添加按钮分两组——「创作」(图片/视频/Agent/预演台/角色)与「规划」(絵コンテ/ネーム/关卡);纯展示分组,无语义过滤。
3. **canvases.type 列与后端接口冻结保留**(双方言不删列惯例):存量值不动,PATCH type 接口保留但前端无入口;新建请求不再携带 type,恒落后端缺省 `general`。
4. **已建类型 UI 退役**:新建画布对话框撤类型卡(退化为名称输入);IP 详情页画布区平铺(按最近更新);编辑器面包屑撤类型徽章。
5. ADR 0004 的定案 1(IP 两层容器)、定案 3(角色是 IP 级实体)、定案 4(素材 IP 归属)**不受影响**。

## Considered Options

- **半翻(类型降级为纯徽章)**:新建仍可选类型、IP 详情页仍按类型分组,仅节点不再过滤——留下「画布徽章 + 节点分组」两套平行的组织系统,且新建时的类型选择不再产生任何后续影响,纯认知负担。放弃。
- **保持画布类型**:机制空载即纯债务;特色节点的原始动机(媒介专属工具)被证明不成立。放弃。

## Consequences

- 后端领域边界与 50 号票落地时一致:解释「画布属于哪个 IP」,不解释图内节点/边与类型语义;类型从此完全不解释(此前仅透传)。
- 「特色节点」概念废止;53-55 号票的絵コンテ/ネーム/关卡为**通用新节点**,进「规划」组。
- 存量画布的 type 值(收编的 animation 等)成为不可见的库内历史事实,无清理动作。
- 将来若真出现「节点行为依赖媒介」的工具(而非仅展示分组),重新引入约束时应有比画布类型更实的载荷,并另立 ADR。
- README 创作画布段中四类画布/特色节点的表述随 53 号票实现一并更新(定案不先行改文案,50 号票先例)。

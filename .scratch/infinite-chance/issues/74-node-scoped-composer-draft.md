# 74 composer 草稿按节点独立(2026-11-03 grill-with-docs 定案)

Type: feat
Status: implemented(2026-11-03 定案当日 implement-spec 落 feat/74-75-composer-draft-picker-header;双轴评审 + 用户裁决修复轮收口,518 测试全绿;遗留浏览器点验)。**口径注记**:见文末「实现增补(2026-11-03)」——①发送成功产物节点随迁来源草稿、composer 显示严格不变(用户裁决);②「选中即接管」实现为首次编辑物化(避免任务回填后输入框停旧快照);③上传参考归属 = 上传发起时选中节点。

## Question

每次打开新的图片节点或视频节点,生成对话框里都显示上一个节点的提示词与参考条——对照即梦/可灵/MJ web 等平台(生成面板随任务/素材独立,新任务空提示词、参数记住偏好),composer 是否应按节点独立?

现状(已查证):composer 草稿是 `CanvasEditorView.vue` 内按模式各一份的内存单例 ref(`composerPrompt` :617 / `videoPrompt` :633),文件头注释明写「切换不清空」;工具栏「+图片/+视频」新建节点只写干净节点 data(`{url:'', note:''}`,`graph.ts:351`)不碰草稿,选中切换 watch(:654-661)只复位拆下标记与模式——因此任何新建/选中的图片或视频节点都显示上一次留在编辑器里的提示词 + 残留上传参考条。该行为是 27 号票第 4 条的**明确风险接受**:「草稿按模式全局、不随选中节点切换,切节点后上一次的提示词仍可见于输入框」。节点自身已有 `data.prompt`/`data.model`(27 号票发送落板),但只在卡片上只读展示(`MediaPrompt`),不回填 composer——输入框与节点内容长期两张皮。直通入口(cut→画面 :2559、cut→视频 :2505、设定图预设 :2656/:2672、角色登场 :2694)整条覆盖草稿,是当前唯一的重置路径。

## 定案(2026-11-03 grilling)

1. **键位变更(Q1 选 b)**:草稿从「按模式全局单份」改为**「节点 × 模式」为键的会话内存 Map**;仍不落 localStorage/服务端,纯前端。选中哪个节点就显示哪个节点的草稿;A 节点写一半切到 B 再切回,各自未发送编辑都不丢。
2. **新建节点初始状态(Q2 选 b,内容清、参数 sticky)**:工具栏「+图片/+视频」新建时,该模式新草稿的提示词与参考条为空;**模型/比例/分辨率/透明背景/带IP风格/时长 sticky 保留上次使用值**(image/video 两模式各自 sticky)。「模型目录变化且当前值无效才落 list[0]」的既有 watch(:663-681)兼容不动。
3. **存量/无草稿节点回落(Q5 选 a)**:选中从未有过草稿的存量旧节点时,回落显示 `node.data.prompt`(上次实际发送、与卡片展示一致)+ 该节点 `data.url` 产物 chip(本来就是派生显示);参数用 sticky 值;无 `data.prompt` 则空。选中即「接管」为该节点草稿,此后编辑互不影响别家。回落按「节点 × 模式」查草稿,两模式同规。
4. **发送成功后提示词与参考图都不变(用户明确)**:27 号票「发送成功不清空」语义原样保留,只是键位从模式改为节点;发送后 `data.prompt/model` 照旧落板,该节点草稿与落板内容自然同步,方便迭代下一版。
5. **对 27 号票的推翻范围**:撤销其第 4 条的风险接受条款「草稿按模式全局、不随选中节点切换」;「提示词落节点」「历史节点回填」「发送成功不清空」(推翻 21/24 号票清空定案的结论)均保留。CONTEXT.md「生成对话框」词条随实现回写(标注推翻 27 号票风险接受)。
6. **随附语义**:
   - 上传参考图(`uploadedRefs`/`uploadedVideoRefs`)归入「上传当时选中节点」的草稿,不再全局残留显示到别家节点;
   - 直通入口整条覆盖语义不变,覆盖目标 = **当时选中节点的草稿**(「参考条整条替换、不带其他会话残留」注释口径照旧);
   - 删除节点时清理其草稿键,防 Map 泄漏;
   - 选中切换 watch 的其余行为(视频节点锁 video 模式、图片节点重置为 image 模式)保持现状。

## 边界

- **改动面**:只动 canvas/web 的 `CanvasEditorView.vue`——草稿 ref 族(:612-649 改 Map)、选中切换 watch(:654-661 回填/接管)、直通写入点(:2505/:2559/:2656/:2672/:2694 键位适配)、上传参考挂接、节点删除清理、模板绑定(:4396-4429);`composer.ts` 如需抽「草稿回落/合并」纯函数则配 vitest;`graph.ts`、`GenerationComposer.vue`(纯 props/emit)、网关、canvas/server 零改动。
- **ADR**:不需要——纯会话内状态键位调整,单文件可逆;推翻 27 号票的理由已在票内记录。

## 验证点

- 新建图片/视频节点:提示词空、参考条空、参数 = sticky;连建两个节点互不影响;
- 选中存量旧节点(有 `data.prompt`):输入框 = 卡片上的提示词,参考条 = 该节点产物 chip;无 `data.prompt` 的为空;
- A 写一半切 B 切回:两边各自草稿保留;
- 上传参考图后切到别家节点:参考图不跟过去;
- 发送成功:输入框与参考条不变,节点 `data.prompt/model` 落板照旧;
- 直通入口(cut→画面/视频、设定图、角色登场):整条覆盖当时选中节点的草稿;
- 删除节点后草稿 Map 无残留;`make test` / `make lint` / `make build` 全绿;浏览器点验。

## Out of Scope

- **草稿持久化**(localStorage/服务端):不做,仍会话内存态——要跨刷新恢复另票。
- **卡片提示词区与 composer 双向同步**(改输入框不回写卡片):现状单向落板不变。
- **27 号票「提示词落节点」链路的任何字段变更**:零改动。

## 实现增补(2026-11-03,评审修复轮,三条已裁决口径)

1. **发送成功随迁严格不变**:验证点「发送成功:输入框与参考条不变」按字面新解会要求产物节点草稿清空重显,评审发现那会违背 27 号票「发送成功不清空」的迭代链语义;用户裁决**以随迁实现**——任务提交成功后把来源节点该模式草稿(prompt + refs)整体复制给产物节点草稿键(`carryNodeDraft` 纯函数,迁「成功时刻」最新值;此后编辑只落产物节点,不回写来源),composer 显示与发送前完全一致。来源节点等待期被删则无草稿可迁,回落路径自然生效;image 发送迁 image Map、video 发送迁 video Map;直通入口的选中时 prefill 整条覆盖语义不受影响(两回事)。
2. **「选中即接管」实现为首次编辑物化**:定案 3 的「选中即接管」不是选中瞬间写键,而是**首次编辑**(patchNodeDraft)时把回落值一并物化为该节点草稿——若选中即物化,任务事后回填 prompt 会被停在输入框的旧快照挡住,回落语义(与卡片展示一致)失效。
3. **上传参考归属 = 上传发起时选中节点**:定案 6 的「上传当时选中」钉死为 `await uploadAsset` **之前**捕获的节点 id(纯函数 `appendNodeDraftRef` 按捕获键落草稿);完成时该节点已被删则静默跳过(无家可归属),不再按完成时选中归错家。

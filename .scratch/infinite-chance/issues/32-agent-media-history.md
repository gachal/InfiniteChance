# 32 Agent 媒体附件与会话历史面板:节点升级为可携媒体的多模态提示词工作台

Type: grilling
Status: approved(2026-10-02 grilling 定案,待实现)

## Question

无限画布中的 Agent 节点需要添加图片和视频的上传功能,用于分析图片和视频;另外聊天中输入的历史记录需要可以保留和查看。日常动线:素材库存一个参考视频,会话内分析、多轮打磨出复刻同款视频的提示词;上传人物三视图,分析设计角色的视频动作。背景:29 号票已把对话历史 `messages[]` 随节点 data 持久化,但「对话流完整展示」被显式列为 out of scope——本票推翻该条;媒体分析通路(素材上传、内容寻址解析、多模态分节)全部现成,本票是拼装而非新建。

## Answer

1. **Agent 节点语义升级(29 号票「纯提示词生产者」改写)**:Agent = **可携媒体的多模态提示词工作台**——调技能生成、反推承接、携媒体分析、投递下游;媒体是会话的参考输入(分析图/视频、以图改提示词、追问细节),产出仍是文本,投递语义不变。不是新节点类型,是同一节点的能力扩展;图片/视频生成仍一律走媒体节点 + 生成对话框(29 号票收口不动)。

2. **17 号票分析节点保留,不收编**:媒体节点上的一键「分析」动作(固定指令 → 结构化分镜/四节报告 → 落独立只读节点)与 Agent 的自由指令多轮分析并存——轻量一键出报告落新节点,与追问式打磨可手编可投递,场景不同,互不取代。

3. **媒体附件,输入侧双入口**:输入框旁附件按钮(本机上传,经 `/api/assets/upload` 入素材库,`uploads/` 归档语义,图片与视频共用一个入口)与「从素材库选」轻量选择面板(复用既有 `GET /assets` 列表 API,按 kind 过滤、缩略点选、可多选)。「日常存的参考视频/三视图」从库中秒选,不重复上传;生成对话框的素材库挑选仍留「待补」,composer 不连带。

4. **上限与纪律**:单条消息 ≤4 图 + ≤1 视频,混合允许——图片对齐 21 号票图生图 `image_urls ≤4`,视频对齐 24 号票参考视频 ≤1(聊天轨视频分节计价贵,1 条封顶是成本护栏);保守自限、上游不认时 4xx 原样透出(24 号票哲学)。选中/挑选**即上传**(chip 显示上传中/失败,失败可移除),发送时只传引用;附件 chip(图片缩略/视频徽章)逐个可移除,发送成功即清空进历史,换技能/开新会话连同未发送附件一并清。

5. **消息形状扩展**:`AgentChatMessage` 从 `{role, content}` 扩展 `{role, content, media?: [{ref, kind}]}`;media 只允许挂 user 轮(assistant 带 = 400),ref 持久化**素材内容寻址路径** `/api/assets/{id}/content`(永久地址,整图 JSON 不背 base64,12 号票契约),assistant 轮恒纯文本。20 轮截断照旧,媒体随轮滚出。

6. **服务端契约**:`generate-prompt` / `generate-prompt/stream` 的 `history[]` 扩展 media 字段——逐条 `resolveMedia`(http(s) 直传 / 内容寻址解出素材真实地址并校验 kind / data: URI 拒绝,17 号票同套),单条消息 ≤4 图 + ≤1 视频,单条引用 ≤4096 字符;`conversationMessages` 多模态化:有媒体的 user 轮拼 content 分节(**媒体在前文本在后**,17 号票形状;图片 `image_url`、视频 `video_url`),无媒体轮纯文本,技能指令首条恒纯文本。流式端点同套支持,媒体校验失败属流前校验,照旧回答 JSON 错误、流不开始。来源标记恒 `gen=prompt` 不变(同一动作的扩展,不拆审计桶,媒体轮的 token 量自己会说话)。

7. **历史媒体全量重发(成本决策)**:每轮请求携带会话中出现过的全部历史媒体(29 号票「每轮全量重发」的媒体版)。护栏两层:单条上限(4 图 + 1 视频)+ 20 轮截断(旧媒体滚出历史自然不再付费);成本真被打穿再立滑动窗口票,不为想象的问题预付复杂度。该语义保住核心动线:传图分析后纯文本追问,模型仍看得见图/视频(占位符方案会让追问轮一张图都没有,直接残废,故否决)。

8. **会话历史面板(查看侧,推翻 29 号票「对话流完整展示 out of scope」)**:Agent 节点上加「历史」按钮 → 右侧滑出面板(素材/生成记录面板同款范式),**绑定该节点**(点哪个节点开谁的会话),只读展示完整会话流——user/assistant 气泡、媒体缩略、助手输出全文——顶部「清空会话」;输入区旁另补显式「新会话」入口(此前唯一清历史途径是换技能,太隐蔽)。不做单轮删除、不做编辑历史重发(「改写过去」的语义复杂:改了第 3 轮,后面 17 轮算什么,需要时另立票)。节点内平铺与浮层弹出两形态否决:260px 节点撑不住半屏历史,浮层滚动体验差。

9. **边界收口**:历史中素材被删——面板缩略图「素材不可用」占位(14 号票先例),**发送时** `resolveMedia` 显式失败(404 `asset_not_found`),文案指路「开新会话」,不静默降级(违反「不静默兜底」哲学,且模型所见与面板所显不一致更难排查);local 驱动无 `public_base_url` 时上传素材(url 列为空)解析不出 LLM 可达地址——既有行为照旧透出,不做前置探测不做 UI 标黄;视觉能力无能力位——模型目录复用 `/prompt-models`,模型不支持图/视频输入时上游 4xx 原样透出(13 号票先例),节点可见可重试。

## 产出面

`internal/promptgen`(history 媒体校验与解析、conversationMessages 多模态化、流式同套)、`packages/api`(`AgentChatMessage.media`、生成输入类型扩展)、`canvas/web`(AgentNode 附件 chip 与上传/素材库选择双入口、素材选择面板、历史侧滑面板与新会话入口、graph.ts 类型)、`docs/api.md` 用例、CONTEXT.md「Agent 节点」「技能」词条回写。

## 验证点

- 多模态 messages 最终形状:首条指令(纯文本)+ 历史带媒体 user 轮的 content 分节(媒体在前文本在后)+ 本轮输入;assistant 轮带 media = 400。
- 带媒体流式端到端(SSE 帧形状不变)与同步端点;媒体校验失败 = 流前 JSON 错误、流不开始。
- 计费对账:媒体轮 token 跳升属预期(全量重发),`gen=prompt` 归桶不变。
- 历史素材删除后的发送失败(404 `asset_not_found`,文案指路清会话)与面板「素材不可用」占位;清空会话后恢复。
- 20 轮截断含媒体轮(旧媒体滚出不再重发);换技能/新会话清未发送附件。
- 素材库选择面板的 kind 过滤与上限校验(第 5 张图/第 2 个视频拒收);本机上传与库选两路引用形状一致(内容寻址)。
- 视频 `video_url` 分节与上游兼容性:25 号票「第三方镜像文档实现、真 key 复核」验证项在本通路延续。
- local 部署(无 `public_base_url`)上传素材发送失败的错误形状如实。

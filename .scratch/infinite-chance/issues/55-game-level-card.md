# 55 游戏关卡卡节点

Type: feat
Status: drafted(2026-10-24 grilling 定案;通用画布回归后(53 号票)为通用新节点)

## Question

游戏侧的核心工件是关卡设计与 GDD 的 level flow(研究纪要 3.3)。50 号票预切时只有「关卡实体卡」五个字。与分镜类节点不同,关卡卡是**文档型**工件:结构化字段(名称/目标/节拍)+ 画面参考(概念图/地图草图),没有「画面块序列」的编辑层诉求——53 号票定案:关卡卡**卡内直接编辑,不开编辑层**。字段保持克制:机制标签/敌人配置表/奖励表等游戏性字段现在加是猜,真用上另票。

## Answer

- 第九种节点类型 `level`,进工具栏「规划」组,`NODE_TYPE_LABEL` =「关卡」,全画布可用。
- 节点数据存整图 JSON(后端零改动):`{ name: string(缺省「新关卡」), goal?: string(一句话目标), detail?: string(详细描述,长文本), beats: string[](流程节拍列表,有序,每拍一行文本), asset_ids: number[](画面槽,素材引用列表,上限 9 与参考图口径一致) }`。
- **卡内直接编辑**:卡面 = 名称 + 目标 + 节拍数 + 画面缩略;「展开」就地展开全部字段编辑,再点收起;节拍列表增删 + 上移/下移按钮(序号显示时生成 1..N 不持久,同 53/54 纪律)。
- **画面槽两入口**:AssetPicker(scope=ip 默认)+ 本机上传(挂画布 IP);**不提供落图动作**(概念参考非生成锚点;要生成经素材面板/AssetPicker 插入图片节点走既有链)。
- **不参与连线**(不加边类型——关卡卡是文档卡,无来源/投递语义,与角色引用节点的「不连线」同族)。
- 添加即「新关卡」+ 空节拍;删除节点 = 图 JSON 删节点,素材行不动;引用素材被删画面槽显示「素材不可用」占位(既有契约)。

## 产出面

- `canvas/web`:`graph.ts`(level 类型/初始 data/节拍序号纯函数)、`LevelCard` 组件(卡内编辑 + 展开收起)、纯函数 vitest。
- 后端与 `packages/api`、`admin-web` 零改动。

无。

## 验证点

## Out of Scope(另票)

- 关卡间顺序关系(画布空间表达即可,不加序号字段);机制标签/敌人配置表/奖励表;关卡图(地图式关卡布局视图);与预演台联动(关卡 → 3D 摆台)。

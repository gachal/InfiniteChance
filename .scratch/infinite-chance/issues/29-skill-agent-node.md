# 29 技能与 Agent 节点:提示词节点升级为可调技能、多轮对话的提示词生产者

Type: grilling
Status: approved（2026-10-01 grilling 定案,待实现）

## Question

提示词节点(11 号票)形态老化:模板下拉 + 主题一次性生成,无迭代、无技能心智。参考即梦类产品的 Agent 节点(截图):通过 `/` 调用「技能」生成图片/视频提示词,技能在网关后台配置。Agent 节点的 MVP 范围、技能与现有提示词模板的关系、提示词如何输出给图片/视频节点、以及多轮对话(定案补充)怎么落?

## Answer

1. **Agent 节点取代提示词节点(不是新增第五类并存)**:节点类型 `prompt` → `agent`;加载旧画布时就地映射(读图归一,自动保存后落库为新值),历史 prompt 节点的 `text` 直接成为 Agent 节点文本区内容,无迁移损失;历史连线不清洗。范围上**不搬**即梦的任务列表(待开始/无任务)与独立悬浮 composer——Agent 是我们对提示词生产节点的升级,不是通用 Agent 运行时。

2. **技能 = 提示词模板演进,同一实体**:`prompt_templates` 原地加列 `description`(技能卡副标题,可空)与 `target`(`image|video|any`,缺省 `any`),MySQL 与 SQLite 双方言 EnsureSchema 同步落;表名与 API 路径(`/admin/prompt-templates`、`/prompt-templates`)不动,UI 与文档全面改名「技能」。`{topic}` 占位符约束保留。**不做图标缩略图**,技能卡 = 名称 + 描述 + 目标徽章。`target` 纯展示 + 浮层筛选,后端零行为、投递不校验(提示词文本通用,单管理员误投无成本,不上锁)。

3. **Agent 节点 = 纯提示词生产者**:职责收口为「调技能生成 + 反推承接 + 投递下游」。**删除内联文生图 row**(10 号票遗留入口,无尺寸/比例参数,与 21 号票 composer 范式分裂;图片/视频生成统一走媒体节点 + composer)。图片/视频节点**不调技能**。13 号票视频反推的落点从「新提示词节点」改为**新 Agent 节点**(连线不变),同样可编可投,反推→改→投回媒体节点再生成的闭环保持。

4. **输入区 = 单框融合 + `/` 技能浮层**:节点底部一行主输入框——打 `/` 唤起技能浮层(名称/描述搜索、↑↓回车选、图/视频目标徽章、可按目标筛选);选中后技能名成节点上可删的 chip,继续输入的文本即主题/修改意见,回车或生成按钮提交;聊天模型下拉保留在旁;不选技能也可对话(见 5),主题为空的裸回车不提交。上方文本区 = 当前提示词草稿(生成落点,可手编)。

5. **多轮对话**:`messages[]`(role+content)存 Agent 节点 data,随整图 JSON 自动保存持久化(27 号票「数据随身」先例),服务端零新表;历史上限 20 轮,超出截断最旧。`POST /canvases/:id/generate-prompt` 请求体扩展可选 `history[]`:服务端首条指令 = 技能渲染文本(**技能改为可选**——未选技能时用内置通用「提示词书写」指令作首条,反推/分析固定指令先例),拼接历史与本轮输入调 `/v1/chat/completions`;聊天轨计费、来源标记 `gen=prompt`、不进 `canvas_tasks`(11 号票先例)均不变。**换技能 = 开新会话**(清历史重算);UI 只渲染最新结果于文本区,完整历史落 data 不展开(节点保持紧凑)。

6. **投递 = 推模式,沿连线**:生成成功即自动把提示词写进**所有下游连线的媒体节点** `prompt` 字段(27 号票已有字段;产物 `url`/`asset_id` 不动,仅覆盖 prompt);无下游连线时结果只留本节点。文本可手改,改完点节点上「投递」按钮重推一次(无下游媒体节点时按钮禁用)。下游投递不按技能 target 校验(见 2)。

7. **显式 out of scope**:技能图标缩略图、Agent 任务列表、独立悬浮 composer/「我的技能」全局面板(技能浏览浓缩进 `/` 浮层)、对话流完整展示、后端会话表、投递按 target 硬校验。

8. **产出面**:`internal/prompttemplate`(加列 + Normalize + 目录形状)、`internal/promptgen`(history 拼接、内置通用指令、目录接口带 description/target)、wiring 双方言 EnsureSchema、`admin-web`(模板页改技能管理页)、`canvas/web`(graph.ts `AgentNodeData`、PromptNode 重写为 AgentNode、编辑器接线与投递逻辑)、`packages/api`(类型扩展)。CONTEXT.md 回写「技能」「Agent 节点」「节点」「视频反推提示词」等词条。

9. **验证点**:历史画布含 prompt 节点的加载与就地迁移落库(含 prompt→prompt 等旧边的展示容忍);多轮 history 的聊天计费对账(每轮全量历史重发,token 随轮递增属预期);投递到多下游 / 无下游 / 下游含分析节点(只投媒体节点)三态;技能被停用/删除后会话 chip 悬空的处理(目录刷新收回,沿用现有 templateId watch 语义,已投递文本不受影响);`{topic}` 渲染 + history 拼接的最终 messages 形状(首条指令 + 历史 + 本轮输入)。

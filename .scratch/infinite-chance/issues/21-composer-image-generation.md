# 21 对话框式图片生成(生成对话框 + 图生图通道)

Type: grilling
Status: implemented（2026-09-29 按定案实现:canvas 后端图生图通道 —— `canvas_tasks.image_refs` 列（MySQL ensureColumn/SQLite PRAGMA 迁移双方言,JSON 数组,空 = NULL）+ `POST /canvases/:id/tasks` 收 `image_urls`（≤4 条逐条 resolveImageRef 解引用、data URI 拒绝、video 任务不读）+ `Client.EditImage`（先拉参考图字节 ≤8MiB/张,组 multipart 打 `/v1/images/edits`,单张 `image`/多张 `image[]`,OpenAI 错误体进任务行）+ worker 按 `ImageRefs` 有无分流 generations/edits;前端 —— GenerationComposer 单实例悬浮层（选中贴节点正下方、未选中停靠底部中央、草稿持久、参考条 = 选中产物 chip + 18 号票上传入口、尺寸预设默认不传、模式位仅「图片生成」）+ 编辑器 submitImageTask 统一提交路径（结果节点先落库再提交、发送后自动选中新节点、无来源落视口中心）+ ImageNode 媒体卡片化（280px 大图、选中描边、hover 下载,图生视频/分析表单暂留）。测试:handler 参考图校验/解析、client edits multipart 形状与失败原因、worker 分流二选一、MySQL/SQLite 参考图往返与旧表迁移;go test 全绿,vue-tsc/eslint 全过,vitest 73 过。VOD 通路多参考图行为仍为运行时验证点（见「待补」））

## Question

参考即梦式「对话框」交互(画布上是产物,选中产物 → 下方对话框改提示词 → 重绘,
连续迭代),无限画布的图片生成交互与界面如何改造?对话框挂载方式、与既有节点内
嵌表单的关系、上下文(参考图)语义、后端图生图通道与参数面如何定?

## Answer

1. **交互范式:对话框成为图片生成的统一入口,节点回归产物展示**。范式决策
   (统一入口 vs 两套并存 vs 只换生图链路;单实例 vs 每节点内嵌)记
   [ADR 0002](../../../docs/adr/0002-composer-paradigm.md)。分阶段落地:本票只
   收编**图片生成**——视频节点(反推/分析)不动,图片节点上既有图生视频/分析表单
   暂留卡片底部,待后续视频票收进对话框模式;底栏模式下拉本票仅「图片生成」一项,
   结构上为 视频生成/分析/反推 预留。

2. **挂载与状态:单实例悬浮层跟随选中**。选中图片节点 → 对话框贴其正下方
   (视口内 clamp),该节点产物自动进参考图缩略条;未选中图片节点 → 停靠画布底部
   中央(从零文生图,结果不连线)。提示词草稿/模型/尺寸是**全局持久草稿**,不随
   选中切换清空;选中非图片节点 → 参考条清空、草稿保留。

3. **迭代语义**:发送 = 提交画布任务;结果落新图片节点并**自动选中**,参考条随之
   切到新产物 → 「选中产物 → 改提示词 → 重绘」连续迭代。参考条可点 × 移除,移除
   后发送走文生图,**连线仍建立**(表达迭代来源,与是否传参考图解耦)。落图纪律
   沿用 10 号票:结果节点与连线先入图、autosave flush 落库、再提交任务。

4. **图生图通道(后端)**:canvas 图片任务收参考图列表 `image_urls`(≤4 条,每条
   ≤4096 runes;厂商 http(s) 地址或 `/api/assets/{id}/content` 内容寻址引用;
   `resolveImageRef` 泛化为列表解引用,data URI 沿例拒绝)。worker 按**有无参考
   分流**:无参考走 `/v1/images/generations`(现状不变),有参考走
   `/v1/images/edits`(multipart 按渠道重建,多参考图 = 多个 `image[]` 文件分节,
   字节与 header 保留语义同 07 号票)。计费仍按次轨(单价 × 尺寸系数 × 单张),
   失败/重试/重启恢复语义不变。**网关零改动**——openai 通路的 edits 中转 07 号票
   已有;VOD 通路的**多参考图行为是本票显式验证点**(单参考已由 20 号票覆盖)。

5. **参考图来源与上传**:缩略条「+」= 本机上传,复用 18 号票
   `POST /api/assets/upload` 入库,以素材内容寻址引用进列表(顺手获得转存与
   跨画布复用)。上限 4 张为前端常量,超出拦在入口。素材库挑选作来源、拖拽入条
   等留后续。

6. **参数面**:底栏 = 模式下拉(见 1)+ 生图模型下拉(`/image-models` 同源)+
   尺寸预设下拉 + 发送按钮。尺寸预设:**「默认」= 不传 size**(维持现状),预设表
   为前端常量,首版 1:1 `1024x1024`、16:9 `1792x1024`、9:16 `1024x1792`,后续按
   各上游兼容性增删;上游不认的 size 由 4xx 透出、节点上可见可重试(与直连同命)。
   **张数固定单张**:canvas 契约无 n,多张 = 多次发送,多张落多节点另票。

7. **图片节点新形式**:视觉翻新为干净媒体卡片(大图、圆角、选中描边,截图样式),
   **图生视频/分析两个既有表单原样暂留卡片底部**(本票不移除);hover 加「下载」
   小按钮(内容寻址同源直取 blob 下载,现有节点无下载能力,顺手补齐);排队/
   失败/素材不可用占位与重试语义不变。

8. **小默认(已向用户报备)**:发送后新节点自动选中;未选中文生图结果落视口中心
   附近;错误展示沿用顶部横幅;composer 不做小屏/触屏适配(桌面形态为主)。

9. **验收**:画布端到端跑通「文生图 → 选中产物 → 对话框改提示词 → 图生图迭代」
   全链,产物/连线/素材引用正确,刷新与关开页任务不丢;curl 级验证带 `image_urls`
   的 edits 任务落素材;VOD 渠道多参考图实测一次;`vue-tsc` / `vitest` / `eslint`
   / `go test` 全绿(本机 vite build 假失败不算回归,正式构建走 Docker)。

10. **Out of scope**:视频节点翻新与图生视频/分析/反推收编(后续视频票)、多张
    n、素材库挑选参考图、截图工具栏的超分/图层拆分/多宫格/宫格切分/全景/拼图
    (网关无对应能力,不虚设入口)、图上「替换」按钮。

## 修订（2026-09-29,用户反馈）

对话框不再常驻:**仅在选中图片节点时出现**(Answer 2 的「未选中停靠画布底部中央」移除——打开新画布即存在且无法删除的形态不是想要的)。工具栏添加的空图片占位节点成为文生图锚点:对话框发送**直接填入该节点**(不新建节点、不连线,任务绑定原节点,产物由任务同步写回);有产物或已有任务绑定的节点发送仍落右侧新节点并连线。`submitImageTask` 的 `sourceNodeId` 相应改为必传,「无来源落视口中心」路径删除;填入路径同样先 autosave flush 再提交任务(锚点节点多半还在防抖窗口里)。CONTEXT.md「生成对话框」词条同步修订。

### 修订二（同日,用户反馈):参数区拆为比例 × 分辨率

Answer 6 的合并尺寸单选拆成**比例、分辨率两个下拉**:比例 自动/1:1/16:9/9:16/4:3/3:4,分辨率 自动/1K/2K/4K;编辑器 `composer.ts` 组合表产出具体像素串走既有 size 透传(双自动 = 不传;单选一轴按 1K/1:1 兜底;1K 档 16:9 由 1792x1024 近比旧值改为精确 1920x1080)。注意:4K 在 tencent-vod 渠道受 relay `vodSizeConfig` 现有「长边 ≥2048 → 2K」两档映射限制,会被归入 2K —— 若 VOD 支持 4K 档,需在 22 号票的 adaptor 映射里补 ≥4096 → 4K;新尺寸未配 size_factors 按次轨规则恒 ×1.0 计价。

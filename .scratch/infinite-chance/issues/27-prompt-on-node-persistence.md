# 27 提示词持久化:节点随身携带 prompt/model + 对话框草稿保留

Type: grilling
Status: approved（2026-09-30 grilling 定案,待实现）

## Question

图片/视频节点的提示词在点击生成后「不见了」:21/24 号票定案发送成功后清空对应模式的提示词草稿,且 `MediaNodeData` 没有 prompt 字段——提示词只落在 `canvas_tasks` 行里,界面任何地方都看不到。产物与提示词如何永久配对?对话框清空行为是否维持?

## Answer

1. **节点持久化(定案)**:`MediaNodeData` 增加可选字段 `prompt` 与 `model`;**提交任务时**写入结果节点——填入路径写锚点节点自身,新建路径写新建的结果节点,随既有自动保存落盘。失败任务同样留提示词(重试时可见当时生成的是什么);重开画布、换设备,产物与提示词恒配对。服务端零改动(画布整图 JSON 自带持久化)。

2. **历史节点回填**:`syncTaskToCanvas` 在任务成功写回 url/asset_id 时,若节点缺 `prompt`/`model` 而任务行有,则一并补写(任务行自 10 号票起就存 prompt/model)——27 号票之前生成的旧产物,重开画布轮询到任务行后自动长出提示词,无需数据迁移。

3. **节点卡片展示**:产物下方增提示词区——默认截断约 3 行,点击展开全文,带复制按钮;模型名小字随行。字段缺省的历史节点(回填前/无任务节点)不显示该区,向后兼容。

4. **推翻 21/24 号票「成功后清空提示词」定案**:发送成功后 prompt **保留**在草稿(模型/参考条本来就保留),改一版直接重发即迭代链。理由:节点持久化后「清空防丢」的前提不复存在,且与「草稿其余部分保留」的既有行为不一致——独独清 prompt 本来就不自洽。风险接受:草稿按模式全局、不随选中节点切换,切节点后上一次的提示词仍可见于输入框,不看清楚就发会造出重复节点——输入框内容肉眼可见,且发送恒落新节点连线、不覆盖既有产物,风险可控。

5. **视频模式同形**:`videoPrompt` 同样保留;视频任务的 prompt/model 以同款字段落视频节点(24 号票的锚点/新建落点语义不变)。

6. **产出面**:`canvas/web`(graph.ts 的 `MediaNodeData`、CanvasEditorView 提交路径与 syncTaskToCanvas、ImageNode/VideoNode 卡片提示词区、纯逻辑抽 composer.ts 配单测);CONTEXT.md「生成对话框」「节点」词条回写(标注推翻 21/24 号票清空定案)。

7. **验证点**:prompt 含超长文本(数千字)时节点的展示与画布 JSON 体积(截断展示、全文入库,不设硬上限,与 canvas_tasks.prompt 同规);填入锚点路径(空视频节点文生视频)与新建路径两条落点都写入字段。

# 71 元素参考生视频(资产库实体同框/登场 + 玩法预设 + 首帧参考互斥修正)(2026-11-01 grilling 定案)

Type: feat
Status: approved(2026-11-01 grill-with-docs 定案,Q1–Q14 全按推荐;未实现。纯前端 canvas/web,网关与 canvas/server 零改动)

## Question

参考 [SHUO-Canvas](https://github.com/ashuoAI/SHUO-Canvas)(仓库零源码、闭源双许可,只借产品形态,见 [调研纪要](../research/shuo-canvas.md)),要「N 个元素整合出视频」——典型场景:**双角色同框/互动视频**、**单角色「耍帅登场」视频**;同时盘点它有哪些功能值得参考。

现状:网关 `/v1/videos/generations` 的 `references`(≤9)与 Seedance(方舟)/ MiniMax H3(原生、百炼)三家 adaptor 已通;composer 视频模式有参考条 + 角色标记;AssetPicker 有角色→变体 / 场景 / 道具分组;70 号票有设定图取图规则与 cut 角色注入;59 号票有 `@图N`;69 号票有风格段。缺口:参考 chip 不知道「这张图是谁」(52 号票定案 chip 不带角色标注),上游只认「图N」;场景/道具无注入通道;composer 无预设。调研中另核出 **70 号票 cut→视频预填与「首帧/参考互斥」冲突**(已上线缺陷,见 A 节)。

## 定案(2026-11-01 grilling)

### A. 首帧/参考互斥修正(Q5;修 70 号票 C 节)

1. **事实**:方舟 Seedance 官方 API 原文「图生视频-首帧、图生视频-首尾帧、全模态参考生视频(包括参考图、视频、音频)为 3 种互斥场景,不可混用」;MiniMax H3 原生与百炼同口径(CONTEXT.md「阿里云百炼渠道」)。70 号票 `onStoryboardGenerateVideo`(`canvas/web/src/views/CanvasEditorView.vue`)在 cut 有画面又标了出场角色时,把 cut 画面作 `first_frame`、角色设定图作 `reference_image` 一起预填——三家视频渠道必拒(70 号票测试只走假上游,未暴露)。
2. **改法**:cut 有画面(`asset_id > 0`)= 画面作**真首帧**、**不注入**角色设定图;cut 有出场角色时 toast「cut 已有画面作首帧,出场角色设定图未注入(首帧与参考不能混用)」。cut 无画面 = 照 70 号票 C 节注入设定图,但以 **B 节元素 chip** 形态注入(`element.type=character`、变体 = 默认变体),自动进绑定行;截断与 toast 计数照旧。cut 画面(图片)直通的注入不变(生图无此互斥)。
3. **composer 通用提示**:视频模式参考条上首帧/尾帧与任一参考角色(`reference_*`)同时在场时,参考条下出一行提示(`GenerationComposer.vue` 的 `vref-hint` 同款范式),文案「首帧/尾帧与参考图/视频/音频不能混用(Seedance、MiniMax H3 会拒);要首帧效果可只传参考图,并在提示词里写明哪张作首帧」——**不拦发送**(上游裁决原则不变)。
4. 实现建议:把 `onStoryboardGenerateVideo` 的参考条预填抽成纯函数(输入 cut、IP 角色目录、上限;输出参考条、截断数、是否因首帧跳过注入),便于单测。
5. 若真 key 实测发现「只首帧」路径角色样貌在运动中跑偏,再议官方变通(cut 画面改作第 1 张参考图 + 提示词指定其为首帧),本票不做。

### B. 元素(Q1 / Q6 / Q7 / Q8 / Q11)

1. **定义**(CONTEXT.md「元素」):资产库实体——角色(连同所选造型变体)/ 场景 / 道具——在一次生成里的出场引用;**一元素一图**,带名称与类型。本机上传或从素材库平铺列表挑的散图仍是无名「参考图」,**不是元素**。生成编排 = 元素一律作参考图、一次多参考直出(现有 `references` 通道,网关零改动);「先合成同框关键帧 → 图生视频」两步链不做一键编排。
2. **数据形态**(只活在 composer 草稿,不上网关、不落库):`ComposerRef` 与 `VideoComposerRef`(`canvas/web/src/composer.ts`)加可选 `element?: { type: 'character' | 'scene' | 'prop'; entityId: number; variantId?: number }`。**名称不存快照**——渲染与发送时按 entityId 从 IP 目录实时取(角色走编辑器既有 `ipCharacters`,场景/道具照其先例补目录缓存);实体或变体已不存在 = 该 chip 退化为无名参考图(角标消失、不进绑定行)。上送载荷 `composerImageUrls` / `composerVideoRefs` 形状不变(element 不出前端)。显示名由编辑器解析后下传 composer(组件不直连 API)。
3. **挑选入口**(Q8):复用 AssetPicker。资产视图(角色→变体两级、场景/道具一级)点选时 `toggle` 事件载荷扩为 `(asset, element?)`,平铺素材视图不带 element;`libraryAsset` 合成记录不变。composer 收到带 element 的 pick:
   - 视频模式角色**恒 `reference_image`**(不走 44 号票默认角色规则;chip 上的角色切换对元素 chip 禁用,title「元素固定为参考图」);
   - 同一实体已在条上(角色按 entityId + variantId 区分,场景/道具按 entityId)→ **替换**该 chip 的图(保持一元素一图),toast「已替换「小蓝」的参考图」;
   - 同一张图再点 = 取消(既有 toggle 语义);
   - 上限守卫照旧(`VIDEO_ROLE_CAPS`、三类合计 ≤9、图片模式 `MAX_COMPOSER_REFS`),超限整条拒收。
4. **chip 展示**:元素 chip 在既有编号角标(59 号票)之外加名称 + 类型小标(角色/场景/道具);同一角色多个变体同时在条上时名称带「·变体名」。
5. **绑定行**(Q6;建议新纯函数模块 `canvas/web/src/element.ts`):
   - 形状:`出场元素:小蓝@图1(角色)、阿红@图2(角色)、天台@图3(场景)`;元素 chip 才进行,无名图不进;无元素 = 空串(行为逐字节不变)。
   - 编号 = 参考序:图片模式按参考条全部条目序(与 `composerRefMentions` 同口径,含自动入条的节点产物 chip),视频模式只数 `reference_image`(与 `videoRefMentions` 同口径)。
   - 显示名:同一角色以多个变体同时出场时补「·变体名」(`小蓝·战斗服@图2`),只一个变体时不带;不拼描述文本(身份靠图);标签与分隔不用 `【】`(避开字幕风险)。
   - 发送拼装(图片/视频 `onComposerSend` 两路都接):在 `styledSendPrompt` 之后插入——结果以风格段(`STYLE_SEGMENT_MARK`)开头则插在风格段那一行之后,否则置于最前;提示词已含同一绑定行不叠加(69 号票 `prependStyleSegment` 同款纪律)。发出的全文随任务行与结果节点 `prompt` 落库,可审计。
   - 预览:提示词框下方只读一行「将附加:出场元素:…」;**不改写输入框**。
   - 字面用「图N」,与 chip 角标、`@图N` 同一套(Seedance 官方写作「图片N」,真 key 若有差异改一个常量)。
6. **@ 浮层**(调研纪要 §3 第 1 条「元素名引用」):元素 chip 在浮层条目上显示名称与类型,选中插入**纯名字**(如「小蓝」——不带 `@`、不随参考序移位),名字与图的对应由绑定行承担;无名图维持 `@图N`。`MentionCandidate`(`refmention.ts`)加可选显示字段,插入走既有 `insertMentionToken`(token = 名字)。
7. **数量**(Q7):不设新上限,与其他参考共用 9 张额度;角色元素超过 4 个时参考条下提示行「出场角色超过 4 个,Seedance 等模型稳定性会下降」,不拦发送(Seedance 官方:超过 4 人稳定性下降)。
8. **两模式**(Q11):元素 chip 与绑定行在图片、视频两模式都生效(手工两步链「先出同框关键帧」也吃到名字绑定);玩法预设仅视频模式。
9. **口径修订**:52 号票「chip 不带角色标注」推翻;`AssetPicker.vue` 头注释与 `libraryAsset` 注释同步改写。

### C. 玩法预设(Q3 / Q10 / Q14)

1. **存放**:canvas/web 代码常量(建议 `canvas/web/src/presets.ts`),不进技能库、不调 LLM、无管理面;仅视频模式。LLM 扩写走 Agent 节点 + 技能的既有路径。
2. **入口**:提示词框旁「玩法」下拉(不做 `/` 触发——composer 正文里 `/` 本身常用,下拉更好发现)。
3. **填名**:`{角色1}` / `{角色2}` = 参考条元素 chip 序中第 1 / 2 个角色元素的显示名(同 B5 显示名规则);`{场景}` = 第 1 个场景元素;道具不进首批模板(照进绑定行);多出的元素不进模板正文、照进绑定行。
   - **必需槽**(角色)缺失 → 留可见占位「〔角色1〕」「〔角色2〕」;
   - **可选从句**(模板里 `[…]` 包住、含 `{场景}` 的片段)缺场景元素时整段省略,有场景时去掉方括号并填名。
4. **行为**:提示词空 → 直接写入;非空 → 替换前确认;只写提示词,不动时长/比例/分辨率/模型;模板文本不用 `【】`;纯写入动作,不记「当前预设」状态。风格不碰(由 69 号票「带 IP 风格」开关管)。
5. **首批四个模板(定稿)**,语法:`{角色1}` `{角色2}` `{场景}` 为占位,`[ ]` 为可选从句:
   1. **单角色登场**:{角色1}[在{场景}]登场:空镜开场,{角色1}从画面深处缓步走出,低角度仰拍缓慢推近,风吹动衣摆与发丝;{角色1}站定,转身直视镜头,摆出标志性姿势定格。节奏先慢后快,电影感光影,{角色1}的样貌与服装和参考保持一致。
   2. **单角色造型展示**:{角色1}[在{场景}]原地站立,姿态自然放松;镜头以{角色1}为中心水平环绕一周,依次呈现正面、侧面与背面,最后回到正面中近景;光线均匀柔和,{角色1}的样貌、服装与配饰细节和参考保持一致。
   3. **双角色同框互动**:{角色1}与{角色2}[在{场景}]同框:两人并肩而行、边走边交谈,{角色1}侧头看向{角色2},{角色2}笑着回应;中景双人镜头,镜头缓慢跟随并轻微环绕,自然光,氛围轻松;两人的样貌与服装分别和各自参考保持一致,不要混淆。
   4. **双角色对决**:{角色1}与{角色2}[在{场景}]对峙:两人隔着一段距离对视,风起尘扬,镜头在两人面部特写之间来回切换,气氛紧绷;随后两人同时冲向对方,交锋瞬间转慢动作,冲击波四散,画面定格在交锋一刻。高对比电影感光影,两人的样貌与服装分别和各自参考保持一致,不要混淆。

### D. 直通入口(Q9)

1. **角色引用卡「生成登场视频」**(`components/nodes/CharacterNode.vue` 新动作,与「生成设定图」并列):编辑器 `onCharacterGenerateEntrance(nodeId, { character, variant })`,照 `onCharacterGenerateSheet` 范式——
   - 落空**视频**节点(源节点右侧 380px、按出边数纵向级联)+ `connectNodes` 来源边 + 选中;
   - 视频草稿预填:参考条整条替换为该角色的元素 chip——变体 = 卡片当前选中变体,取图 = 该变体最新视图类 > 该变体任意设定图 > 角色任意图(封面投影),即 70 号票 `pickCutCharacterRefs` 的优先级,抽成「按变体取图」共享函数(`sheet.ts`)两处共用;变体与角色都无图时不带 chip,toast「该造型还没有设定图,建议先生成设定图」;
   - 提示词 = `prependStyleSegment(单角色登场模板填名, ipStyle)`(69 号票直通先例:风格段拼最前);时长/比例/分辨率不动;
   - 人工确认后发送(花钱操作总案 Q5)。
2. **连线矩阵**:`EDGE_MATRIX.character` 加 `'video'`(`connection.ts`);头注释加「character → video 登场视频生成来源边(71 号票)」,「character 仅可作设定图来源边的源」改为「仅可作生成来源边的源」。边只表达生成来源;历史已存边不清洗不校验。
3. cut→视频无画面时注入的角色 = 元素 chip(A2)。
4. 不做:资产库抽屉入口(无画布任务 kind 仅 image,ADR 0007);双角色直通(需要两个角色,走 composer)。

### E. 边界

- **改动面**:只动 canvas/web;网关、canvas/server、任务契约、`canvas_tasks` 与任何表**零改动**——元素只活在 composer 草稿与发出的提示词里。
- **不做 / 另票**:两步一键编排(同框关键帧 → 图生视频);cut 的 `scene_ids` / `prop_ids` 出场字段与注入(65/70 号票欠账;场景/道具多半还没有图);声音元素(角色音色说台词——Seedance 参考音频锁音色 / 万相 2.7 `reference_voice` / Vidu `voice_id` 三路线不同);图片模式预设;`generate_audio` 开关(Seedance 缺省 true,自带同步音频);按模型特判(MiniMax H3-Max 不支持多模态参考,由上游 4xx 透出);网关 `references` 契约扩「主体」(接 Vidu / 可灵时再议)。
- **候选池**(调研纪要 §4,按价值排序,本票后逐个 grilling):多镜头拼接成片、分镜批量生成 + 按目标模型格式重写、视频分析 → 分镜板导入、宫格切分/拼图、Vidu 原生渠道、百炼加挂万相 3.0 / 2.7。
- **帮助浮层**(68 号票 `canvas/web/src/canvasHelp.ts`):补「元素」「玩法预设」「生成登场视频」三条(内容模块改文案,零组件 diff)。
- **70 号票票面**:C 节加修正指针(已随本票落笔)。
- 花钱操作永不进 Agent 工具循环(63 号票纪律):登场直通与预设都只是预填,发送仍人工确认。

## 验证点

- **纯函数单测**(vitest):
  - 绑定行:两模式编号口径、多变体补名、无元素空串、风格段开头时的插入位置、已含同一行不叠加;
  - 预设填名:必需槽占位、可选从句省略与填名、多余元素不进正文;四段模板字面量在测试里钉住(改文案须改测试,防静默漂移);
  - 元素 pick 合并:视频模式角色恒参考图、同实体替换、同图取消、上限拒收、实体已删退化;
  - 按变体取图的优先级(与 `pickCutCharacterRefs` 共用后两处结果一致);
  - cut→视频预填:有画面不注入 + 跳过标记、无画面注入为元素 chip、截断计数;
  - 连线矩阵:character → video 可连,character 仍不可作任何边的目标。
- **构建与点验**:`make test` / `make lint` / `make build` 全绿;浏览器点验——composer 两模式挑元素出角标、绑定行预览、@ 浮层插入名字、「玩法」下拉替换确认、角色卡登场直通落节点与边、cut 有/无画面两路预填、互斥提示行与超 4 角色提示行。
- **真 key 验证点**:
  1. 69 号票风格段「【画面风格】」是否被 Seedance 当字幕渲染(二手资料称 `【】` 表字幕,说法互相矛盾);
  2. 绑定行写「图N」与官方「图片N」的绑定效果差异;
  3. 双角色一致性(Seedance 2.0 / 2.5、MiniMax H3 原生 / 百炼);
  4. 修正后 cut 有画面路径(只首帧)不再被上游拒;
  5. 超过 4 个角色时的稳定性提示是否合理。
  - 方舟账户若仍欠费(2026-10-12 实证为总阻断),须先充值才能验。

## Out of Scope

- 见 E 节「不做 / 另票」与候选池。
- 元素持久化到节点或任务行(元素标注不出 composer 草稿;要复现同一组元素,靠发送后草稿保留——27 号票)。
- 元素的跨画布/跨 IP 引用(元素即本 IP 资产库实体,AssetPicker 资产视图本就限本 IP)。

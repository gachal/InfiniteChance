# 64 剧本节点(script)与原文承载(2026-10-31 grilling 定案)

Type: feat
Status: implemented(2026-10-31 实现;feat/script-pipeline)。**口径注记**:①packages/api 零改动——`CanvasGraph` 刻意宽松(`nodes: unknown[]`),script data 不跨 API 边界;②30 万字超限取「层内横幅警示不阻断输入」而非硬截断,护 IME 与粘贴流。定案背景:2026-10-31 grilling 定案;与 65 号票可并行;「剧本」三种用途的载体票,分段读工具在 66;平台参照:剪映 Hub「剧本节点拆分镜组」、LTX Studio 脚本入口)

## Question

「一句话/小说 → 分集剧本 → 分镜」需要文本产物的画布载体:分集大纲、每集剧本、长篇小说原文。行业形态(即梦短剧工作室/度加/seko):先出 2-3 个故事方案供选再展开分集大纲 → 完整剧本,支持 10 万字级长文解析。当前画布没有承载「长文本创作产物」的节点类型(分析节点只读、Agent 文本区是会话工作区、絵コンテ是分镜板不是剧本)。

## 定案(2026-10-31 grilling)

1. **新节点类型 `script`(「剧本」)**:第 12 种节点类型,工具栏「规划」组;data = `{ title?, text }` 纯文本——场次用 markdown 场头约定(如「【第N场|内|日|地点】」),**不做结构化场次编辑 UI**(LLM 读纯文本无损失,结构化编辑器 YAGNI)。
2. **编辑承载 = 编辑层浮层**(絵コンテ 40 号票范式家族):卡面折叠摘要(title + 摘要行/字数),整卡点击进编辑层全文编辑(大 textarea,自动保存走既有 scene-change → updateNodeData → autosave 链);不开卡内直接编辑(一集剧本数千字,关卡卡范式装不下)。
3. **三种用途一个类型**:**分集大纲**(大纲画布)/ **每集剧本**(每集画布)/ **原文**(小说原文节点);title 区分(「分集大纲」「第3集剧本」「原文:书名」)。不新增「大纲节点」「原文节点」类型。
4. **原文大文本**:上限 **30 万字**(前端校验,超出提示分段粘贴);代价注记:大文本进节点 data 使整图 JSON 变重(30 万字 ≈ 1MB,autosave 全量提交;单用户本地部署可接受);txt 文件上传入口显式另票。原文的消费走 `read_source` 分段读工具(66 号票:按节点 id + rune 区间),本票只落载体。
5. **连线**:script 节点**不作任何连线的源与目标**(照角色卡/关卡卡先例;内容经 Agent 工具读写,不靠边;EDGE_MATRIX 不扩)。
6. **「先选后展」不建专门 UI**:2-3 个故事方案供选 → 用户选定 → 展开的节奏写进内置系统提示词(66 号票),对话内完成。

## 验证点

- 30 万字原文节点的 autosave 重量实测(整图 JSON 提交耗时;超预期再议「原文单独入库表」备选,定案已留)。
- 编辑层编辑长文本的输入体验(IME 组词/滚动/自动保存节流)。

## Out of Scope

- 结构化场次编辑器;剧本→分镜的结构化解析 UI(解析是 LLM 工具行为,不是表单)。
- txt/epub 文件上传(素材嗅探表不收文本,另票)。
- 跨画布引用剧本内容(集组织 = 每集一张画布,见 63-67 总案)。

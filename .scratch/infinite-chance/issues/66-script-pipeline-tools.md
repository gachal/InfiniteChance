## Question

63 号票落了循环运行时,本票定义 LLM 可调的领域工具集与「剧本导演」系统提示词——让「把这段小说变成 80 集短剧」一句话启动全链:先出 2-3 个故事方案 → 选定 → 分集大纲 → 逐集剧本 + 分镜板,途中自动建角色/场景/道具;且**已有角色先行的时序**(用户先在角色库建好角色再投小说)必须成立——不重建、不覆盖用户已有设定。

## 定案(2026-10-31 grilling)

1. **六工具内建**(63 号票机制,代码定义 tools 数组,不可配置):
   - `create_character` / `create_scene` / `create_prop`:纯文本资产入库(名称/别名/描述/细节),不出设定图(65 号票定案 5);返回实体 id。
   - `list_assets`:读本 IP 已有角色(name/alias/description/detail)与场景/道具(name/description/detail),供一致性引用与对表;不返回设定图。
   - `save_outline` / `save_script`:落分集大纲/每集剧本 script 节点(payload = title+text,前端应用落图,63 号票定案 3)。
   - `save_storyboard`:落絵コンテ节点,cuts 为 53 号票结构、画面 asset 空(「未配画面」占位;67 号票扩字段落地后自然携带 character_ids/景别)。
   - `read_source`:按 script 节点 id + rune 区间分段读原文(避免 10 万字全文进每轮对话;区间大小实现定,建议 1-2 万 rune/段)。
2. **角色对表(character reconciliation)**:系统提示词强制纪律——剧本工作开始前**必须先 `list_assets`**;分析文本时逐实体对表(名称/别名/描述匹配),**命中即复用已有 character_id 禁止重建**,拿不准(笔名/外号/译名差)在对话里问用户确认,不静默猜;未命中才 create_*;场景/道具同理。已匹配实体在产物中统一用库内名称/别名。覆盖两种时序:**角色先行**(先建角色带设定图再投小说——cut 的 character_ids 引用既有角色,后续落图/生视频经 52 号票图像锚带设定图、台词将来吃角色 voice_id(57 号票);两条链路本期不实现,引用字段为其铺路)与**小说先行**。
3. **内置系统提示词**(「剧本导演」指令):先选后展节奏(2-3 个故事方案供用户选再展开,64 号票定案 6);行业默认参数(短剧 60-100 集、每集 1.5-2 分钟、每集 10-15 分镜,对话参数可覆盖);对表纪律;工具使用守则(产物分批落,每集一个 save_script + 一个 save_storyboard)。
4. **集组织**:短剧 = 一个 IP,每集 = 一张画布(EP01…),大纲放一张「大纲画布」;**跨集批量(一键生成 N 张集画布)不在本票**——用户逐集进画布让 Agent 工作;剧集目录/跨集管理轻量版另票。

## 验证点

- 全链真演:一段 5000 字小说 → 方案选择 → 大纲 → 选定一集 → 剧本 + 分镜板落图 + 角色/场景/道具入库。
- 对表三分支各验一遍:命中复用 / 新建 / 追问确认。
- 15 轮护栏下的长任务收尾质量(80 集大纲一循环放不下时正确分批、引导续跑)。
